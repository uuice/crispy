# Middleware Optimization

## 优化的中间件执行顺序

### 执行顺序 (从早到晚)

1. **静态文件优化中间件** (`applyStaticMiddleware`)
   - 为静态文件添加缓存头
   - 优化静态资源的性能

2. **静态文件服务** (`express.static`)
   - 服务浏览器构建文件
   - 服务上传文件 (`/uploads`)
   - 服务静态生成页面 (`/static`)

3. **性能监控中间件** (`performanceMonitor`, `memoryMonitor`)
   - 监控响应时间
   - 监控内存使用情况
   - 添加性能相关的响应头
   - **重要**：在静态处理之前应用，避免响应头冲突

4. **静态页面处理器** (最高优先级 HTML 缓存)
   - 检查并服务预生成的静态 HTML 文件
   - 跳过 API 和管理路由
   - **重要**：这是 HTML 缓存的第一道防线

5. **基础中间件** (`applyMiddleware`)
   - CORS 中间件
   - 请求体解析 (JSON, URL-encoded)
   - 请求日志记录

6. **路由性能优化** (`optimizeRoutePerformance`)
   - 根据路由类型设置适当的缓存头
   - 优化不同类型资源的缓存策略

7. **模板引擎配置** (`configureNunjucks`)
   - 配置 Nunjucks 模板引擎

8. **API 路由** (`apiRoutes`)
   - 处理所有 API 请求

9. **博客路由** (`blogRoutes`)
   - 处理博客相关请求

10. **错误报告端点**
    - 处理客户端错误报告

11. **Swagger 文档路由**
    - 提供 API 文档访问

12. **Angular 应用路由** (条件性页面缓存)
    - 在生产环境中应用页面缓存
    - 处理 Angular SSR

13. **404 处理器** (`notFoundHandler`)
    - 处理未找到的路由

14. **全局错误处理器** (`globalErrorHandler`)
    - 处理所有未捕获的错误

## 性能优化特性

### 1. HTML 缓存优先级 (最重要)

- **静态页面处理器** 位于第4位，确保 HTML 缓存最高优先级
- 避免不必要的中间件执行，直接返回预生成的 HTML
- 这是性能优化的关键：HTML 缓存 > 所有其他中间件
- **重要**：性能监控在静态处理之前，避免响应头冲突

### 2. 静态文件优化

- 静态文件优先处理，避免不必要的中间件执行
- 长期缓存 (1年) 用于静态资源
- 内存缓存用于频繁访问的页面

### 3. 性能监控

- 响应时间监控
- 内存使用监控
- 慢请求警告
- 性能指标响应头

### 4. 路由特定优化

- API 路由：无缓存，严格限制
- 静态文件：长期缓存，不可变
- HTML 页面：短期缓存 (5分钟)

### 5. 缓存策略

- **HTML 缓存**：最高优先级，直接文件系统访问
- 内存缓存：30秒 TTL
- 数据库缓存：60秒 TTL
- 静态文件：1年缓存

## 使用建议

1. **开发环境**：启用详细日志和性能监控
2. **生产环境**：启用页面缓存和性能监控
3. **监控**：关注慢请求和内存使用情况
4. **优化**：根据性能监控结果调整缓存策略
